# Complexity Calculating RCE

This is a personal project with the aim of assisting students and educators when it comes to the topic of the time complexity of algorithms. It implements two approaches for estimating an algorithm's complexity: one module measures the execution time of the provided script in regard to its input size and then tries to fit a function to it.
The second approach analyzes the syntax trees of languages and calculates the complexity by counting the number and evaluating the structure of operations (loops, recursive calls, etc.). 

## Use 
General:
To use the web app, the starting function needs to be identifiable (e.g. for python this would be "def main(n):"). Otherwise, the analysis tools don't know where to begin. 
The Language-Dropdown lets users select their programming Language (currently only Python is implemented).

On Dynamic Analysis:
When one wishes to receive dynamic analysis, it is necessary to select the appropriate input type.
The number of test data points directly correlates to the number of test runs of different input sizes. 
Fewer test runs are more volatile to noise, and more test runs increase the risk of reaching the app's resource limits.

(API Documentation gets generated by FastAPI see the relevant domains /api/docs for the necesary information)

## Limitations
Neither the dynamic nor the static analysis satisfies the requirements for a rigorous scientific complexity analysis.
After all, the empirical measurements conducted here are influenced by other traffic on the server and consequently, more noisy than local tests.
The syntactical analysis also takes "shortcuts" and focuses more on expected implementations rather than checking all possible edgecases.

These limitiations were necessary due to the deployment platform and the resource limitations it encounters. 

## Future considerations 

One might be able to extend the abilities of the static analyser, expand the number of supported languages and inputs and improve the sandboxing technology.
